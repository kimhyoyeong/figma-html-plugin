# Figma HTML Export (figma-html-plugin)

Figma 시안을 **반응형 HTML/CSS 초안**으로 변환하고,  
AI를 활용해 **heading 구조와 이미지 alt를 자동 개선하는** Figma 플러그인입니다.

---

## 1. 개요

AP 주요 업무인 **헤라 라이브러리 페이지**, **설화수 커버 페이지** 제작을 위해 개발된 Figma 플러그인입니다.

해당 업무는 일반적으로 **PC·모바일 두 벌의 디자인을 각각 작업한 뒤 반응형으로 구현**하는 방식으로 진행됩니다.  
이 과정에서 디자인을 코드로 옮기는 작업은 수작업으로 이루어지며, **최소 약 2일 이상의 공수**가 소요됩니다.

본 플러그인은 이러한 초기 퍼블리싱 작업을 자동화하여,  
작업 시간을 단축하고 전반적인 업무 효율을 향상시키기 위해 제작되었습니다.

---

## 2. 주요 기능

- Figma 시안을 **HTML/CSS 초안**과 **이미지 에셋**으로 변환
- **레이어 구조 기반 마크업**
- 텍스트·이미지 **규칙 기반** 변환
- 레이어명 기반 자동 설정 **`code-*`** 규칙 (`code-btn`, `code-slide`, `code-raster`, `code-video`)
- **AI 기반** heading / alt 제안 및 반영

---

## 3. 사용 방법

Figma에서 플러그인을 임포트한 후,  
ROOT에 해당하는 PC / 모바일 프레임을 선택하고 **분석**을 실행합니다.

### 3.1 레이어 탭

- 레이어 트리 기반 구조 확인
- 각 노드 속성 및 구성 정보 확인

### 3.2 코드 / AI

- 생성된 HTML/CSS 코드 확인
- AI 분석: **생성된 HTML/CSS**와, 분석용 이미지(비용 최적화를 위해 축소·인코딩된 이미지 사용)를 함께 보내 heading 구조·이미지 alt 등을 제안하고, 즉시 반영 가능
- **EXPORT_ZIP 버튼**을 통해 HTML + 이미지 다운로드

### 3.3 미리보기

- PC / 모바일 화면 확인
- 결과물 1차 검증

---

## 4. 동작 구조 (핵심 로직 요약)

### 4.1 분석 및 입력

- 선택한 ROOT를 기준으로 레이아웃 분석을 수행합니다.
- ROOT가 1개인 경우 PC 기준으로 단일 분석을 진행하며,  
  2개 이상일 경우 가로 크기를 기준으로 **PC / 모바일을 자동 구분**합니다.
- 프로젝트명, 국가 코드 등의 메타 정보는 **이미지 파일명 및 export 규칙에 반영**됩니다.
- 레이어 이름 규칙(`code-btn`, `code-slide`, `code-video`, `code-raster` 등)에 따라  
  **마크업 구조 및 export 방식이 결정됩니다.**

### 4.2 레이어 탭 (구조 요약)

- 분석 결과, 선택한 ROOT 기준의 레이어 구조를 **텍스트 형태로 요약하여 표시합니다.**
- ROOT 하위의 각 프레임은 **섹션 단위로 구분**되며, 레이어별로 다음 정보가 함께 정리됩니다:
  - 이름 및 타입
  - Auto Layout 정보 (방향, 간격, 패딩)
  - 배경 및 테두리 스타일
  - 섹션 내 상대 위치
- 이는 Figma 전체 문서를 JSON으로 그대로 가져오는 방식이 아니라,  
  **현재 선택된 프레임만을 기준으로 재구성된 요약 데이터입니다.**

### 4.3 레이아웃 처리

- Auto Layout은 flex 기반 구조로 변환됩니다.
- Absolute 레이아웃은 부모 기준 좌표와 크기를 **CSS 변수로 분리하여 처리**합니다.
  - `--ap-left`, `--ap-top`: 기준 프레임 대비 위치 오프셋
  - `--ap-w`, `--ap-h`: 요소의 너비 및 높이
  - `--ap-width`: 전체 기준 너비 (디자인 기준 폭)
- 실제 렌더링 시 `calc(... / var(--ap-width) * 100cqi)` 방식으로 변환되어  
  **디자인 비율을 유지한 반응형 스케일링**을 적용합니다.

### 4.4 HTML / CSS 생성 및 공통화

- 섹션 단위 구조(`ap-section--01` 등)를 기준으로 HTML과 CSS를 생성합니다.
- 생성된 스타일은 요소별로 분산 적용되는 방식이 아니라,  
  **공통 규칙을 기준으로 병합·정리**됩니다.
- 반복되는 스타일은 공통 클래스로 묶고,  
  요소별 차이 값만 남기도록 CSS를 재구성합니다.
- 이를 통해 코드 중복을 줄이고, 유지보수와 확장이 용이한 구조로 변환됩니다.
- 스타일은 생성 이후 한 번에 정리되어 적용되는 방식으로 관리됩니다.
- 필요한 경우 Swiper 구조 및 스크립트도 함께 생성됩니다.

### 4.5 타이포 처리

- 모든 텍스트 스타일은 CSS 변수(`--ap-fs`, `--ap-lh` 등) 기반으로 관리됩니다.
- 줄간 비율 및 스냅을 적용하여 디자인과 최대한 동일한 타이포를 유지합니다.
- PC / 모바일 간 차이 값만 `@media`로 분기 처리됩니다.

### 4.6 이미지 처리

- 이미지는 export 시 자동 생성되며, PC / 모바일 간 **이미지 매칭 로직**이 적용됩니다.  
  (`sourceNodeId`, 레이어 이름, 순서 기준)
- 미리보기에서는 경량 썸네일을 사용하고,  
  ZIP export 시에는 고해상도 이미지를 사용합니다.
- 파일명은 `page_{프로젝트}_sec{섹션}_img...` 규칙으로 생성됩니다.

### 4.7 PC / 모바일 처리

- 섹션 단위로 구조를 비교하여 반응형 전략을 결정합니다.
  - 구조가 동일한 경우 → 하나의 HTML + `@media`
  - 구조가 다른 경우 → `pc-only` / `mo-only` 분리
- PC / 모바일 차이 값은 공통화 이후 단계에서 병합 또는 분리 처리됩니다.
- 최종 export 시 구조와 스타일이 일관되게 정리된 상태로 출력됩니다.

## 5. AI 활용 방식

| 항목 | 설명 |
|------|------|
| 위치 | 코드 탭 (검수 / 반영) |
| 입력 | 생성된 HTML/CSS + 비전용 **JPEG**(원본 고해상도 대신 축소·인코딩된 이미지 사용) |
| 출력 | JSON 제안 (이슈, alt, 헤딩 등). Gemini는 구조화 스키마 |
| 반영 | UI에서 HTML 문자열 패치 |

### 사용 모델 (UI에서 선택)

- GPT-4o, GPT-4o-mini
- Gemini 2.5 Flash

### 역할

AI는 생성된 HTML 결과물을 기반으로 퍼블리싱 품질을 검수하고 개선하는 역할을 수행합니다.

- 이미지(JPEG)를 함께 분석하여, 제품 사용 맥락과 시각 정보를 반영한 alt 텍스트 제안
- 텍스트 구조를 기반으로 섹션별 주요 타이틀을 판단하고, 적절한 heading 구조 제안
- SEO, 접근성, 시맨틱 기준에서 문제를 검수하고 개선 방향 제시

이를 통해 퍼블리싱 과정에서 발생하는 수작업 검수 비용을 줄이고,  
일관된 품질의 결과물을 빠르게 생성할 수 있습니다.

---

## 6. 주의사항 (디자인 협조)

- 레이어 구조 정리 필수
- PC/MO **트리 구조가 유사할 때** 반응형(`@media`) 출력에 유리
- Auto Layout 사용 권장 (절대 배치 비중이 높을 경우 CSS 구조가 복잡해질 수 있음)
